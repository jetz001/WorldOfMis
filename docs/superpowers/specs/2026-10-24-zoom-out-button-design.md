# Zoom-out button design

## เป้าหมาย

เพิ่มปุ่มสำหรับพากล้องถอยออกไปดูภาพรวมโลกอัตโนมัติ เพื่อให้ผู้ใช้ไม่ต้องพึ่งเมาส์กลางหรือการหมุนสกอลล์บ่อย ๆ เวลาต้องการกลับไปเห็นภาพรวมของลูกโลก

## ปัญหาปัจจุบัน

ตอนนี้แอปมีพฤติกรรมเด่นคือกดเลือกหมุดแล้วกล้องบินเข้าไปยังจุดนั้น แต่ยังไม่มีทางลัดสำหรับกลับออกมาที่มุมมองภาพรวมโลก ผู้ใช้จึงต้องซูมด้วยอุปกรณ์ชี้ตำแหน่งเอง ซึ่งไม่สะดวกโดยเฉพาะเวลาทดลองดูหลายหมุดต่อเนื่องกัน

## แนวทางที่เลือก

เพิ่มปุ่มบน `Navbar` ในกลุ่มปุ่มควบคุมด้านขวาบน เมื่อกดแล้วจะเรียกฟังก์ชันในคอมโพเนนต์แผนที่เพื่อ `flyTo` กลับไปยังมุมมองภาพรวมโลกแบบนุ่มนวล แทนการกระโดดเปลี่ยนค่า `zoom` ทันที

แนวทางนี้เหมาะกับ UI ปัจจุบันเพราะผู้ใช้มองหาปุ่มควบคุมหลักที่แถบบนอยู่แล้ว และไม่ไปทับพื้นที่การ์ดด้านล่างซ้ายหรือ tooltip บนแผนที่

## ขอบเขตการเปลี่ยนแปลง

- `src/App.tsx`
  - เพิ่ม state หรือ signal สำหรับสั่งให้แผนที่รีเซ็ตมุมมอง
  - ส่ง callback ให้ `Navbar`
  - ส่งค่าหรือ trigger ต่อไปยัง `GhostGlobe`

- `src/components/UI/Navbar.tsx`
  - เพิ่มปุ่มใหม่ในแถบ action controls
  - ใช้ไอคอนที่สื่อความหมายเช่นการขยายมุมมองออกหรือการดูโลก
  - ตั้งข้อความให้กระชับ เช่น `ดูโลก` หรือ `ซูมออก`

- `src/components/Globe/GhostGlobe.tsx`
  - เพิ่มฟังก์ชันสำหรับพากล้องกลับไปยังมุมมองเริ่มต้นของโลก
  - ใช้ `map.flyTo(...)` พร้อม `center`, `zoom`, `speed`, `curve`
  - คงพฤติกรรมเดิมของการเลือกหมุดและการ hover marker ไว้

## พฤติกรรมที่ต้องการ

เมื่อกดปุ่ม:

- กล้องค่อย ๆ ถอยออกไปยังมุมมองโลกกว้าง
- จุดศูนย์กลางกลับไปยังตำแหน่งตั้งต้นของแอป
- ไม่ล้าง `selectedPin`
- ไม่ปิด drawer หรือเปลี่ยนข้อมูลเรื่องเล่าที่เลือกอยู่
- ไม่กระทบปุ่มซูมและเข็มทิศของ `NavigationControl`

## ค่าเริ่มต้นของมุมมอง

มุมมองปลายทางควรอิงกับค่าเริ่มต้นที่ใช้ตอนสร้างแผนที่ใน `GhostGlobe` เพื่อให้พฤติกรรมสอดคล้องกัน ได้แก่:

- `center: [100.5, 13.75]`
- `zoom: 2.8`

ค่าความลื่นไหลของแอนิเมชันควรอยู่ในโทนเดียวกับการบินไปยังหมุด แต่เน้นความนิ่งและอ่านทางสายตาง่าย อาจใช้ `speed` ต่ำกว่าการบินเข้าหาหมุดเล็กน้อย

## การจัดการสถานะ

มีสองทางเลือกหลัก:

1. ส่ง callback ลงไปให้ `GhostGlobe` ผ่าน props แล้วให้ `GhostGlobe` เปิดเผยเมธอดการซูมออกผ่านการเปลี่ยน signal
2. ย้าย logic มุมมองแผนที่ขึ้นไปส่วนกลางมากขึ้น

สำหรับงานนี้จะเลือกแบบแรก เพราะเปลี่ยนน้อยกว่าและเข้ากับโครงสร้างปัจจุบันที่ `GhostGlobe` เป็นเจ้าของ `mapRef` โดยตรง

รูปแบบที่เหมาะคือให้ `App` ส่งค่า trigger แบบตัวนับหรือ timestamp ไปยัง `GhostGlobe` ทุกครั้งที่ผู้ใช้กดปุ่ม จากนั้น `GhostGlobe` ใช้ `useEffect` เฝ้าดู trigger นี้แล้วเรียก `flyToWorldView()`

## การรองรับข้อผิดพลาด

- ถ้าแผนที่ยังไม่สร้างเสร็จ (`mapRef.current` ยังเป็น `null`) ปุ่มต้องไม่ทำให้แอปพัง
- ถ้าผู้ใช้กดปุ่มซ้ำระหว่างกำลังบินกล้องอยู่ ให้ MapLibre จัดการ transition ต่อได้โดยไม่ต้องมี state เพิ่มที่ซับซ้อน
- ถ้าเลือกหมุดใหม่หลังจากซูมออกแล้ว พฤติกรรมเดิมต้องยังบินเข้าหาหมุดได้ตามปกติ

## ผลกระทบด้าน UX

- ลดการพึ่งพาเมาส์กลางและสกอลล์
- ทำให้ผู้ใช้สลับระหว่าง “ดูจุดเฉพาะ” กับ “ดูภาพรวมโลก” ได้เร็วขึ้น
- ลดความรู้สึกหลงทางหลังจากบินเข้าไปหลายตำแหน่งติดกัน

## การทดสอบ

- เปิดแอปแล้วกดปุ่มใหม่จากมุมมองเริ่มต้น ต้องไม่เกิด error
- คลิกหมุดให้ซูมเข้า แล้วกดปุ่มใหม่ กล้องต้องถอยออกไปมุมมองโลก
- กดปุ่มหลายครั้งติดกัน แอปต้องไม่ค้าง
- หลังซูมออกแล้ว คลิกหมุดอื่นต่อ ต้องยังบินเข้าได้
- ตรวจสอบบนจอเล็กว่าปุ่มไม่ชนกับปุ่มเดิมใน `Navbar`

## สิ่งที่ยังไม่ทำในรอบนี้

- ซูมออกอัตโนมัติเมื่อไม่มีการใช้งานตามเวลา
- ปุ่มลอยบนแผนที่แยกจาก `Navbar`
- การปรับคำแปลในระบบ `i18n` ทั้งชุด ถ้าจำเป็นจะเริ่มจากข้อความตรงในปุ่มก่อน แล้วค่อยเก็บงานแปลให้ครบในรอบถัดไป
